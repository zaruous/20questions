# 구조와 설계

[← README로](../README.md)

## 파일 맵

```
server/game.js        게임 규칙 전부. I/O·타이머 없는 순수 함수, 시간은 인자로 주입(now)
server/index.js       WebSocket/HTTP 서버. 고정 방 3개, 연결·방 목록·브로드캐스트·1초 틱, 끊긴 자리 유예, dist/ 정적 서빙
server/*.test.js      규칙 단위 테스트 + 실제 소켓을 붙이는 통합 테스트
src/useGameSocket.js  자동 재접속, 좌석 복구(sessionStorage 토큰), 서버 시계 오차 보정
src/screens/Home.jsx  닉네임 + 방 목록
src/screens/Game.jsx  대기실(첫 출제자 지정) / 진행 화면(참가자·질문 게이지·상황 줄·피드·입력)
src/styles.css        디자인 토큰과 레이아웃
render.yaml           Render 블루프린트 (docs/deploy.md 참고)
```

## 설계상 중요한 세 가지

1. **서버 권위** — 모든 상태는 서버가 소유하고, `viewFor(room, playerId)`가 플레이어별로 볼 수 있는 것만
   화이트리스트로 골라 내보냅니다. 정답 단어는 출제자 본인과 라운드 종료 이후에만 포함됩니다.
   클라이언트로 내려가지 않으니 DevTools로도 볼 수 없습니다. 통합 테스트가 이것을 실제 소켓으로 검증합니다.
2. **좌석 복구** — 입장할 때 받은 토큰을 `sessionStorage`에 저장해 두고, 새로고침이나 연결 끊김 뒤
   같은 자리로 돌아옵니다. 서버는 연결이 끊긴 자리를 `RECONNECT_GRACE_MS`(기본 5초) 동안 그대로 잡아 두므로,
   그 안에 같은 토큰으로 돌아오면(F5) 방장·출제자 역할과 진행 중인 라운드가 아무 일도 없던 것처럼 이어집니다.
   유예가 지나서야 이탈로 처리합니다: 게임 중이면 자리를 남겨 두고 "끊김"으로 표시하고, 대기실에서는 정리합니다.
   **나가기** 버튼은 `leave` 메시지를 보내 유예 없이 바로 자리를 비웁니다(연결은 유지되어 방 목록으로 돌아갑니다).
3. **방 목록 실시간 갱신** — 아직 방을 고르는 중인 사람에게도 방 상태 변화를 밀어 줍니다.

## 게임 규칙과 I/O의 분리

`game.js`는 소켓·타이머·`Date.now()`를 전혀 모릅니다. 모든 함수가 `(room, ..., now)`를 받아 `room`을 바꾸고
`{ ok, error }`를 돌려줍니다. 덕분에 규칙 테스트는 시간을 마음대로 흘려 보낼 수 있고(`tick(room, T0 + 61_000)`),
`index.js`는 메시지 타입을 함수 호출로 바꿔 주는 얇은 층에 머무릅니다.

## 메시지 프로토콜

클라이언트 → 서버 (`/ws`, JSON):

| type | 필드 | 누가 | 설명 |
| --- | --- | --- | --- |
| `join` | `code`, `name` 또는 `token` | 누구나 | 방 입장. `token`이 있으면 같은 자리로 복귀(자리가 이미 비워졌으면 `fatal` 오류) |
| `leave` | — | 방 안 사람 | 방 나가기. 유예 없이 바로 자리를 비우고, 연결은 유지한 채 방 목록을 다시 받는다 |
| `pickFirst` | `playerId` (null이면 해제) | 방장, 대기실 | 첫 출제자 지정 |
| `start` | — | 방장, 대기실 | 게임 시작 |
| `secret` | `text`, `category` | 출제자 | 단어와 주제 확정 |
| `ask` | `text` | 추측자 | 질문 |
| `answer` | `verdict: yes \| no \| unclear` | 출제자 | 판정 |
| `guess` | `text` | 추측자 | 정답 시도 |
| `next` | — | 방장 | 결과 화면에서 바로 다음 라운드 |
| `restart` | — | 방장, 게임 종료 후 | 같은 사람들과 다시 |

서버 → 클라이언트:

| type | 필드 | 설명 |
| --- | --- | --- |
| `rooms` | `rooms[]` | 방 목록. 입장 전인 연결에만, 변화가 있을 때마다 |
| `joined` | `playerId`, `code` | 입장 성공. `playerId`가 복귀용 토큰 |
| `state` | `state`, `serverNow` | 내 시점의 방 상태. `serverNow`로 타이머 오차 보정 |
| `error` | `message`, `fatal` | `fatal`이면 입장 자체가 실패한 것이라 첫 화면으로 |

## 방 관리

방은 서버 시작 시 `ROOM_COUNT`개를 만들어 두고 생성·삭제하지 않습니다. 1초 틱이 제한 시간을 처리하면서
접속자가 0명인 방을 살핍니다. 끝난 게임은 지킬 것이 없으니 즉시, 진행 중이던 판은 재접속을 60초 기다렸다가
`resetRoom`으로 빈 대기실로 되돌립니다.

연결이 끊긴 사람은 곧바로 이탈로 보지 않습니다. 소켓이 닫히면 그 사람의 자리 비우기를 `RECONNECT_GRACE_MS`(기본 5초)
뒤로 예약해 두고, 그 안에 같은 토큰으로 `join`이 오면 예약을 취소합니다. 새로고침(F5)은 "연결 끊김 → 새 연결이
토큰으로 입장"의 순서로 일어나므로 이 유예 안에 들어오고, 그동안 게임 상태(`game.js`)는 아무것도 바뀌지 않습니다.
게임 규칙은 시간을 모르므로 이 유예는 I/O 계층(`index.js`)에만 있습니다.

## 화면 구성

- 화면 하나가 뷰포트(`100dvh`)를 채우고 스크롤은 안쪽(피드·명단)에서만 일어납니다.
  폰에서 주소창이 늘고 줄어도 바닥 입력창이 붙어 있게 하려는 것입니다.
  키보드가 올라오면(`interactive-widget=resizes-content`) 이 상자도 함께 줄어들어 입력창이 키보드 위에 남습니다.
- 라이브채팅 패널은 뷰포트(`fixed`)가 아니라 게임 화면 상자(`.game.has-chat`) 기준 `absolute`입니다.
  폰에서는 바닥 시트, 넓은 화면에서는 오른쪽 열. 게임의 바닥 입력줄과 같은 밑변·safe-area를 공유해야
  안드로이드 내비게이션 바·키보드에 채팅 입력줄만 잘리는 일이 없습니다.
- 진행 화면은 위에서부터 **헤더(방·라운드·타이머) → 참가자 칩 → 질문 20칸 게이지 → 상황 한 줄 → 피드 → 입력**.
  상황 한 줄은 "누가 무엇을 하는 중인지"를 말해 주고, 내가 움직여야 할 때 노랗게 바뀝니다.
- 대기실은 참가자 카드 목록 자체가 첫 출제자 선택기입니다. 방장에게는 라디오(카드 전체가 탭 영역),
  나머지에게는 같은 카드에 🎩 표시만 보입니다.
- 넓은 화면(≥720px)에서는 참가자가 왼쪽 세로 목록으로 빠지고, 나머지는 같은 구조입니다.
- 색: 주색은 스무고개의 물음표 노랑(결정적인 행동: 시작·정답·확정), 보라는 일상 행동(질문·선택),
  초록/빨강은 판정에만 씁니다. 제목·숫자는 Jua, 본문은 Pretendard(동적 서브셋). 둘 다 못 받아도 시스템 서체로 동작합니다.
- 기본기: `color-scheme: dark`, `theme-color`, safe-area inset, `touch-action: manipulation`, `:focus-visible`,
  `prefers-reduced-motion`, 타이머/점수 `tabular-nums`, 긴 텍스트 `overflow-wrap: anywhere`.

## 테스트

```bash
npm test          # 69개
```

- `game.test.js` (45개) — 입장, 시작, 첫 출제자 지정, 정답 비공개, 질문/답변, 정답 추측, 라운드 진행,
  접속 끊김, 정규화, 고정 방 목록.
- `server.test.js` (18개) — 실제 서버를 띄워 클라이언트 여러 개를 붙이고 한 라운드를 끝까지 진행합니다.
  **정답 단어가 추측자에게 전송되지 않는지**, 방 목록이 실시간으로 갱신되는지, 토큰으로 자리에 돌아오는지,
  방장이 지정한 첫 출제자로 시작하는지까지 확인합니다. 새로고침(F5) 유예도 여기서 검증합니다:
  게임 중·대기실에서 잠시 끊겼다 같은 토큰으로 돌아오면 게임이 그대로 이어지고, 유예가 지나면 자리를 비우고,
  나가기는 바로 비웁니다(테스트에서는 유예를 0.5초로 줄여 띄웁니다).
- `chat.test.js`, `rtc.test.js`, `src/chat/useVoice.test.js` (6개) — 라이브채팅·음성 시그널링 규칙.

CI(`.github/workflows/test.yml`)는 PR과 main 푸시마다 테스트와 빌드를 돌립니다. `vitest`는 서버 코드만 불러오므로
클라이언트(JSX) 오류는 빌드 단계에서 걸립니다.
