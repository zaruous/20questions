# 20고개 (Twenty Questions) — 2~8인 실시간 멀티플레이

React + Vite 클라이언트와 Node WebSocket 서버로 만든 실시간 스무고개 게임입니다.
서버가 **방 3개를 항상 열어 두고**, 참가자는 첫 화면의 방 목록에서 하나를 골라 들어갑니다.
매 라운드 한 명이 출제자가 되어 단어를 정하고, 나머지가 예/아니오 질문 20개 안에 정답을 맞힙니다.

## 실행 (서버 하나로 운영)

서버 한 대가 화면(정적 파일)과 실시간 통신(WebSocket)을 모두 처리합니다.

```bash
npm install
npm run build     # 클라이언트 빌드 → dist/
npm start         # http://localhost:3001  (PORT 환경변수로 변경 가능)
```

`npm start`는 `0.0.0.0`에 열리므로 **같은 와이파이의 폰에서 바로 접속**할 수 있습니다.

```bash
# PC의 내부 IP 확인
hostname -I            # Linux
ipconfig getifaddr en0 # macOS
# 폰 브라우저에서 http://<PC의 내부 IP>:3001
```

서로 다른 네트워크(각자 집, LTE)에서 하려면 공개 주소가 필요합니다.
WebSocket을 지원하는 호스팅에 배포하거나, `cloudflared` / `ngrok` 같은 터널을 **`npm start`(3001)** 에 연결하세요.
(Vite 개발 서버는 외부 도메인 접근을 차단하므로 터널 대상으로 쓰지 마세요.)

개발 중에는 자동 새로고침이 되는 분리 실행도 됩니다:

```bash
npm run dev       # 서버(3001) + Vite(5173, LAN 개방) → http://localhost:5173
```

## 배포 (Render 무료 플랜)

`render.yaml`이 포함되어 있습니다. Render 대시보드에서 **New → Blueprint**로 이 저장소를
연결하면 설정 입력 없이 서비스가 만들어집니다. 수동으로 만들 때는 아래 값을 그대로 넣으세요.

| 항목 | 값 |
| --- | --- |
| Runtime | Node |
| Build Command | `npm ci --include=dev && npm run build` |
| Start Command | `npm start` |
| Health Check Path | `/healthz` |

`--include=dev`가 **반드시** 필요합니다. Render는 빌드 중에도 `NODE_ENV=production`이라
`npm ci`만 쓰면 `vite`가 설치되지 않아 빌드가 깨집니다.
`PORT`는 Render가 주입하고 서버가 그대로 읽습니다. `https`로 열리면 클라이언트도 `wss`로 붙습니다.

무료 플랜에서 알아 둘 것:

- **15분간 트래픽이 없으면 잠듭니다.** 다시 깨는 데 1분쯤 걸리므로 첫 접속자만 기다립니다.
  WebSocket 메시지도 트래픽으로 세기 때문에 게임하는 동안에는 잠들지 않습니다.
- **깨어날 때 메모리가 비워집니다.** 방 3개는 다시 만들어지지만 진행 중이던 판은 사라집니다.
- **인스턴스를 늘리지 마세요.** 방 목록이 프로세스 메모리에 있어서 여러 대로 늘리면 갈라집니다.

## 테스트

```bash
npm test          # 41개: 게임 규칙 단위 테스트 + 실제 WebSocket 통합 테스트
```

통합 테스트는 실제 서버를 띄워 클라이언트 여러 개를 붙이고 한 라운드를 끝까지 진행하면서
**정답 단어가 추측자에게 전송되지 않는지**, 방 목록이 실시간으로 갱신되는지까지 확인합니다.

## 방 구조

| 항목 | 값 |
| --- | --- |
| 방 개수 | **3개 고정** (`ROOM_COUNT` 환경변수로 변경 가능) |
| 방당 인원 | 2~8명 → 서버 전체 동시 참가자 최대 24명 |
| 입장 방법 | 첫 화면 방 목록에서 선택 (방 코드 없음) |
| 게임 중인 방 | 목록에 잠긴 상태로 표시되고 새 사람은 못 들어옴 |
| 빈 방 | 게임이 끝나고 다 나가면 즉시, 진행 중이던 판이면 60초 뒤 대기실로 반납 |

방은 서버 시작 시 만들어지고 이후 생성·삭제되지 않습니다.
사람이 다 나간 방을 자동으로 되돌리지 않으면 3개뿐인 자리가 '게임 중'인 채로 영영 잠기기 때문입니다.

## 게임 규칙

| 항목 | 값 |
| --- | --- |
| 라운드 수 | 참가자 수 (모두 한 번씩 출제) |
| 질문 수 | 라운드당 20개 |
| 단어 선택 제한 시간 | 60초 |
| 질문 단계 제한 시간 | 5분 |
| 점수 | 맞힌 사람 +3 / 출제자는 누가 맞히면 +1, 아무도 못 맞히면 +2 |

- 질문은 **선착순 자유 질문**이고, 답변을 기다리는 동안에는 다음 질문을 받지 않습니다.
  (순번제 대신 선택한 이유: 8명 중 한 명이 자리를 비우면 순번제는 판이 멈춥니다.)
- 정답 시도는 서버가 자동 판정합니다. 공백·문장부호·대소문자는 무시합니다.
- 틀린 정답 시도는 질문 1개를 소모합니다.
- 출제자가 나가거나 단어를 못 정하면 그 라운드는 무효(점수 없음)로 처리됩니다.

## 구조

```
server/game.js        게임 규칙 전부. I/O·타이머 없는 순수 함수, 시간은 인자로 주입
server/index.js       WebSocket/HTTP 서버. 고정 방 3개, 연결·방 목록·브로드캐스트·1초 틱
server/*.test.js      규칙 단위 테스트 + 실제 소켓 통합 테스트
src/useGameSocket.js  자동 재접속, 좌석 복구, 서버 시계 오차 보정
src/screens/          Home(닉네임 + 방 목록) / Game(대기실·출제·질문·결과)
```

설계상 중요한 세 가지:

1. **서버 권위**: 모든 상태는 서버가 소유하고, `viewFor(room, playerId)`가 플레이어별로
   볼 수 있는 것만 화이트리스트로 골라 내보냅니다. 정답 단어는 출제자 본인과
   라운드 종료 이후에만 포함됩니다. 클라이언트로 내려가지 않으니 DevTools로도 볼 수 없습니다.
2. **좌석 복구**: 입장할 때 받은 토큰을 `sessionStorage`에 저장해 두고, 새로고침이나 연결 끊김 뒤
   같은 자리로 돌아옵니다. 게임 중 이탈한 사람의 자리는 남겨 두고, 대기실에서는 정리합니다.
3. **방 목록 실시간 갱신**: 아직 방을 고르는 중인 사람에게도 방 상태 변화를 밀어 줍니다.

## 알려진 제한과 위험

- **상태는 서버 메모리에만 있습니다.** 서버를 재시작하면 진행 중인 모든 방이 사라집니다.
  또한 방 목록이 프로세스 안에 있어서, 서버를 여러 대로 늘리면 방이 공유되지 않습니다.
- **방이 공개됩니다.** 방 코드가 없어졌으므로 서버에 접속한 사람은 누구나 목록을 보고 들어옵니다.
  사적인 방이 필요하면 접속 자체를 제한하거나(사내망, 터널 인증) 코드 방식을 되살려야 합니다.
- **동시 수용 인원은 24명(8명 × 3방)** 입니다. 더 필요하면 `ROOM_COUNT`를 올리세요.
- **폰에서 화면을 잠그면 연결이 끊깁니다.** 좌석은 토큰으로 복구되지만,
  끊긴 사람이 그 라운드의 출제자였다면 라운드는 무효가 되고,
  남은 접속자가 2명 미만이 되면 게임이 종료됩니다.
- **도배 방지가 없습니다.** 길이 제한만 있고 속도 제한은 없습니다.
- **정답 판정은 문자열 비교입니다.** "야옹이"는 "고양이"의 정답으로 인정되지 않습니다.
- **출제자의 예/아니오 판정은 검증할 수 없습니다.** 사람의 선의를 전제로 합니다.
